**Reserved keyword collisions**
- `parmap` reserves `pm_parallel`/`pm_chunksize`/`pm_pool`/`pm_processes`/`pm_pbar` (and their deprecated aliases) for itself and always consumes them before calling the mapped function. If the function's own signature happens to declare a parameter with one of these names, its value was silently dropped with no indication anything was wrong — previously only documented as a convention to avoid, never enforced.
- `parmap` now inspects the function's signature and emits a `UserWarning` identifying the collision. A warning (not a hard `TypeError`) was chosen to avoid breaking existing callers, consistent with how the codebase already handles the `pm_processes=-3` case.
- Verified against the pre-change code that this warning is genuinely new (only the unrelated deprecated-alias warning fired before).
